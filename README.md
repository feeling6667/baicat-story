# baicat-story

> 观众介入型图文故事重构 Agent Skill：把一段故事素材、生活观察或模糊念头，重构成有停留、代入和讨论势能的图文故事。

不做反转机器，不做热点搬运，也不追求把苦难当奇观。它更像一个**故事重构导演**：先让观众对人物“理应怎么做”做出判断，再用人物的选择、真相或命运留白把人留下。

## 它解决什么问题

抖音、小红书上手绘图文的核心从来不是“画得好看”，而是**故事有没有让人留下的理由**。

很多人拿到素材直接拆镜头：事件 → 画面 → 出图。结果要么是流水账，要么是强行反转的“为反转而反转”。评论寥寥，点赞点完就划走。

baicat-story 把整个过程拆成分阶段、手动推进的可控流程，**让评论自然发生在故事里，而不是靠结尾抛一句“你怎么看”。**

## 分阶段手动推进（重要）

本技能**一次只执行一个阶段**，每完成一个阶段就停下，等你输入【继续】才进入下一阶段，严禁自动连做多步。这样每一步都可以先检查、纠错，不会开头错了还一路错到底。

阶段顺序：

1. **素材势能诊断** —— 判断这个故事有没有“观众会介入”的潜力，输出素材势能卡后即停。
2. **定向重构** —— 保留最有价值的冲突核，重排信息顺序，把抽象感受改成可画动作。
3. **互动机制配置 + 结局策略** —— 定一个主情绪轴、一个主观众动作，然后在反常选择/真相反转/开放留白等里选结局。
4. **确认闸门** —— 汇总前几步成果，等你确认后才会进入编排。
5. **图文编排** —— 在确认后按最多 15 格输出分镜，逐格可调整。
6. **发布建议（可选）** —— 需要时再输出标题、封面、标签。

## 核心流程（原概念版，供理解）

1. **素材势能诊断** —— 判断这个故事有没有“观众会介入”的潜力，不硬做。
2. **定向重构** —— 保留最有价值的冲突核，重排信息顺序，把抽象感受改成可画的动作。
3. **互动机制配置** —— 每篇只定一个主情绪轴和一个主观众动作，不堆七个按钮。
4. **结局策略** —— 在真相反转 / 反常选择 / 余震定格 / 开放留白中选最匹配的一种。
5. **确认闸门** —— 用户确认故事核、重构方向和结局后才进入图文编排，最多 15 格。

> 实际执行时按上方**分阶段手动推进**的流程，一次一步，逐步停在每个阶段末尾。

## 全局限制

> **逻辑优先于效果。**

不得为了反转、留白、评论点或情绪冲击硬塞不成立的情节。人物动机、信息来源、时间地点、动作先后、因果关系与已发生事实必须前后一致；发现冲突先指出并修正，不用“留白”遮掩漏洞。

## 使用方法

在支持 SKILL.md 的 Agent（如 Minis、Claude Code）中调用：

1. 拷贝 `SKILL.md` 内容作为技能触发指令，或把本仓库放进 `skills/` 目录。
2. 给出故事素材，或说明题材与想讨论的方向。
3. Agent 会先诊断、重构、定互动与结局，等你确认后再编排图文（最多 15 格）。

推荐搭配手绘出图类技能（如 baicat）：先用本技能产出高质量分镜脚本，再交给出图技能批量生成画面与 HTML 组装。

## 关键设计点

- **开放结局 ≠ 没写完**：冲突必须完整，只是不替观众宣布人物最终命运。
- **已完成的决定不能再被写成悬而未决**：留白只留给尚未发生的未来。
- **不为评论区硬编剧情**：创作者不需要在每格堆上夸张冲突或爽点。
